使用第四阶段最终教师 `2026-10-28_09-31-14_stage4_gap_contact/model_1499.pt`。
本次完善采集器并完成小规模验证，正式采集由用户执行以下命令。

该批数据现已完成并验收；各等级通过率、序列窗口覆盖和后续 WM 指令见
[本次采集验收报告](XZ1九类教师数据采集验收-2026-10-28.md)。

## 推荐首批命令

```bash
cd /home/haozi/桌面/Nazarite-mjlab/Train/Nazarite

uv run --no-sync python -m nazarite.scripts.collect_xz1_wmp \
  --checkpoint logs/rsl_rl/xz1_wmp_him_teacher/2026-10-28_09-31-14_stage4_gap_contact/model_1499.pt \
  --output logs/wmp_data/xz1_teacher_stage4_nine_v2 \
  --all-levels \
  --seeds 42 44 43 \
  --validation-seeds 43 \
  --episodes-per-case 16 \
  --num-envs 16 \
  --episode-seconds 20 \
  --device cuda:0
```

共 243 组、3888 个完整结束回合：8 类障碍各 10 级，加 1 组平地几何，
乘以 3 个种子和每组 16 回合。42、44 为训练种子，43 为验证种子。
成功、接触失败、离开路线和超时回合都保留，不将“完整回合”等同于“通过回合”。
默认地形包含平地、高墙、窄楼梯、窄坡、梅花桩、独木桥、限高框架、轮胎阵列和 gap。

命令保留教师训练配置中的物理随机化、观测扰动、延迟和速度采样，
窄地形保留训练中的中心线纠偏。不要额外加 `--nominal`，除非明确需要关闭这些扰动。
默认相机仍是已有 64×64、10 Hz、58° 垂直视场角和临时仿真安装位姿，
未改变输入契约。

输出目录必须不存在；采集器不会覆盖旧数据，也不支持在中断目录直接续采。
若显存不足，可将 `--num-envs` 降为 8 或 4，保持每组回合数不变。
不同并行环境数会改变随机轨迹，不保证与原并行数逐回合相同。

## 采集器的行为

- 每环境提前分配回合配额。快失败环境完成自己的配额后不再保存新片段，
  必须等待慢环境完成其配额；退役环境仍按仿真要求 reset，但不再积累帧。
- 不指定难度选项时默认覆盖 0–9 级，支持 `--all-levels` 和 `--levels 1 2 9`。
  `--difficulties 0 0.5 1` 作为旧接口保留；三种选项互斥。平地只保存第 0 级。
- 采集器负责越障成功终止：四脚越过末端、躯干越过安全距离、姿态合格、
  至少两脚支撑，并连续稳定 0.2 秒。物理失败和离开路线优先于成功。
  平地使用任意方向 2.4 m 位移，匹配原教师的全向平地指令。
  仅采集环境移除提前结束的 `narrow_course_complete`，保留物理失败条件；
  教师训练任务与 checkpoint 均不改变。
- 独木桥在完成全脚越桥前仍使用桥身走廊边界；完成越桥后按实际 0.8 m
  平台验收，修复此前把桥后正常落地漏计为超时的问题。评测器同步使用相同几何口径。
- 继续保存原 WMP 时间对齐：50 Hz 策略、10 Hz 深度，每张图对应此前五条已裁剪动作。
  reset 后首帧动作块清零。回合在两张图之间结束时只记终止元数据，
  不向序列追加非 0.1 秒间隔的尾帧。
- 原始命令在裁剪前检查有限性；不将 Inf 裁剪成有效训练标签。
  发现非有限命令或奖励即中止并标记数据集为 `interrupted`。

## 输出与检查

输出目录中有：

- `manifest.json`：数据契约、教师路径与 SHA256、相机参数、采集计划、逐回合索引。
- `episode_*.pt`：同步深度、本体观测、HIM 历史、扫描标签、动作标签与动作块。
- `collection_summary.json`：按地形/等级和具体种子案例统计回合数量、真实通过率、
  纯超时失败比例、失败原因、每环境配额及 32/64 帧可用片段数。

每回合新增 `training_level`、`success`、`outcome`、`timeout_failure`、
`time_limit_reached`、`completion`、`crossed_obstacle`、稳定落地时长和机身坐标系
速度指令的均值/最小值/最大值。随机化模式的 `speed_m_s=null`，
避免把未应用的固定速度参数误报为真实采集速度。

`outcome` 为 `success`、`failure` 或 `timeout`。同时发生物理失败和时间上限时，
记为失败，`time_limit_reached` 仍为真；不计入纯超时失败。
完成采集时 `status=complete`，且应为 243/243 组、3888/3888 回合。
这表示配额完成，不代表所有障碍通过。

失败数据继续保留用于 WM 学习；采集器不自动补采到一定成功次数，
避免引入新的选择偏差。完成后先查看分级质量统计，再决定是否补采弱项。
中断时已提交回合保留，但 `status=interrupted` 不直接用于正式 WM 预训练。

## 短序列与下一阶段

部分限高框架等地形约 5–6 秒即可完整通过，序列自然不足 64 帧。
原 WM 采样器会跳过短于 `--batch-length` 的回合；因此不能沿用 64 帧参数
却认为这些地形也被训练到了。此次真实 CUDA 验证中，框架 3/3 回合通过，
均有 60 帧，足够 32 帧窗口，但不够 64 帧。

后续先按 `collection_summary.json` 审核各类型有效片段覆盖。
首批 WM 预训练建议使用 `--batch-length 32`，并保留参考 WMP 的模型和训练实现。
这只调整离线训练窗口长度，不改变 10 Hz 输入、五步动作块、网络结构或部署契约。
不通过跨回合拼接、重复尾帧或强行留在平台上凑足 64 帧。

名义条件的多速度补采可显式使用 `--nominal --speeds 0.3 0.5 0.7`，
并用 `--command-mode course` 标注带纠偏的采集。`--speed/--speeds`
只作用于名义模式；随机化模式保留原教师速度分布，传入这些参数会明确报错。
