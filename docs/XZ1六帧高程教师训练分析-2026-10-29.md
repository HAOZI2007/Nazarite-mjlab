# XZ1 六帧高程教师与 stage2 对比

分析对象：

- 单帧旧教师：`2026-10-27_17-48-42_stage2_fixed_curriculum/model_2499.pt`。
- 六帧新教师：`2026-10-29_10-07-08_height_history6/model_5000.pt`。
  TensorBoard 读到 iteration 5004，最新完整 checkpoint 是 5000。

结论：平均等级约 5.44 主要是最高级通关后随机回采的正常结果，不能解读为只能
通过 level 5。新模型存在慢速最高高墙和比赛限高框架的局部退化，随机训练条件下
最高窄坡和独木桥也有退步；低难度梅花桩则明显改善。本轮不能用平均等级给模型排名，也
不能把所有变化直接归因于六帧输入。

本轮完成日志、配置、代码及 checkpoint 核查，以及 280 回合训练地形推理测评；
后续针对用户反馈，另外完成 47 条 Robocon2027 限高框架诊断轨迹，见末节。
训练参数和策略文件未修改，未启动训练。

## 为什么平均等级停在 5 附近

两轮保存配置及 checkpoint 契约有以下差异：

| 项目 | stage2 | height_history6 |
| --- | --- | --- |
| 环境数 | 800 | 600 |
| rollout 长度 | 100 | 100 |
| 高程输入 | 当前帧 32 维编码 | 6×32＝192 维编码 |
| 完成最高级 | 保持最高级 | 随机回到 0–9 级 |
| 课程契约 | v2 | v4 |
| gap 失败判定 | 足端高度及承重近似 | 实际足端—坑底接触 |
| 热启动来源 | 前一轮 model_1600 | stage2 model_2499 |

奖励权重及 YAML 中的主要物理、随机化、终止参数一致，但函数名称相同不代表
历史代码语义相同；gap 判定已经在 10 月 28 日修正。因此尤其不能将 gap 新旧
训练率的变化全部算作策略能力变化。

旧训练末 100 次平均等级为 **8.10**，各障碍基本长期停在 level 9，平地固定 0。
新训练末 100 次平均等级为 **5.44**，各障碍均值为 5.52–6.37，平地仍是 0。
代码在最高级满足连续成功条件后执行 `torch.randint(10, ...)`，重新分配等级。
回采规则与类型、等级及连续计数绑定的修正仍然存在。

用理想化例子理解：假设每级总能成功、停留时间相同，最高级通过后均匀回到
0–9，再逐级上升。各级被访问频率与 `1,2,…,10` 成正比，平均等级是 6；
再混入 10% 的 level 0 平地，总均值约为 **5.4**。实际回合时长、失败和重采样
都会改变这个值，但它足以说明 5.44 并不意味着课程卡死。

新训练最后 500 次，level 9 的结束回合数是 **13,816**，并非没有最高级样本。
但占全部结束回合的比例从旧训练 **95.3%** 降为 **18.9%**：难度覆盖改善，
最高难度专项训练密度同时明显下降。这是高难度能力保持需要关注的变化，
不构成已经隔离验证的唯一退化原因。

最高窄坡的超时比例从约 2.2% 上升至 7.7%。独木桥超时仍为 0，失败集中在

## 相同条件推理测评

两版均使用当前同一地形、接触检查和独立通过判据，避免直接对比历史评测口径。
seed 43，固定速度 0.4 m/s，起点 x±0.10 m、y±0.05 m、yaw±0.05 rad；
关闭物理随机化、噪声和延迟。窄路线使用 `course` 真值中心线纠偏。
每个条件 4 环境各 1 回合，地形等级 0、5、9，共 216 回合。

结果：除以下两项外，两模型所有测试条件均为 4/4。

| 条件 | stage2 | 六帧 model_5000 |
| --- | ---: | ---: |
| level 0 梅花桩 | 0/4，踩地 | 4/4 |
| level 9 高墙 | 3/4，1 次超时 | 0/4，4 次机身接触 |

这支持局部能力变化，但小批量名义条件测试不能替代随机训练统计，也没有否定
最高窄坡和桥在随机条件下的退化。当前测评不是 Robocon2027 全场连续通过率，
也没有覆盖手柄速度变化、实机雷达或全部随机化。

### 慢速高墙及历史输入诊断

补充 4 组各 4 回合测试，其他条件同上：

| 条件 | 通过 |
| --- | ---: |
| 旧模型，0.7 m/s | 4/4 |
| 新模型，0.7 m/s | 4/4 |
| 新模型，0.4 m/s，六帧全部替换为当前帧 | 3/4 |
| 新模型，0.7 m/s，六帧全部替换为当前帧 | 4/4 |

将 0.4 m/s 的高墙诊断扩大为同批大小 16、各环境首回合，共 48 回合：

| 输入 | 通过 | 失败 |
| --- | ---: | --- |
| 旧模型当前帧 | 12/16 | 3 次机身接触、1 次超时 |
| 新模型正常六帧 | 8/16 | 8 次机身接触 |
| 新模型重复当前帧六次 | 10/16 | 5 次机身接触、1 次超时 |

扩大样本后，历史替换的改善缩小到 2 个回合，不能宣称已证明六帧是唯一根因。
这些是同一模型的推理输入消融，重复帧也是输入分布改变，不等于重新训练的
单帧模型。结论应是：慢速最高墙敏感性明显，历史使用值得继续排查；需要在相同
回采课程下训练单帧对照，才能区分历史结构与课程覆盖对能力保持的影响。

代码与模型检查确认历史顺序、复位和部署接口一致；没有发现顺序颠倒或历史分支
始终为零。最终 actor 的当前扫描权重块范数约 7.42，五个历史块约 2.28–2.46，
证明历史分支参与了学习，不代表已经证明其贡献是正面。
六帧只覆盖 0.10 秒，且历史扫描保留当时机身坐标、没有重投影到当前坐标。
这是结构限制及后续对照因素，不能单凭本轮测试认定为实现错误。

## 数值健康度

末 100 次平均回报旧 15.08、新 15.65；平面速度误差旧 0.172、新 0.143 m/s；
Value loss 旧 0.0198、新 0.0185；HIM estimation loss 旧 0.0224、新 0.0227。
训练分布不同，回报和误差不能直接用来证明越障更强，但没有全局优化发散迹象。
抽查两轮共 14 个 checkpoint，模型及优化器张量均有限。

新训练有 3 次恢复，迭代 2077/3971/4620，分别为高墙 level 9、高墙 level 8、
框架 level 8。现场根状态、关节位置和速度出现 NaN，动作仍有限且约 ±1.5 以内；
没有可用接触对，无法从保存后的现场断言具体碰撞原因。
滑移速度与角动量两个诊断指标各有 3 个非有限值；PPO loss 没有非有限记录。
恢复后训练继续。相对约 3 亿环境步，这些是稀疏故障，缺乏证据将整体能力变化
归因于它们；但也不能将当前物理仿真称为完全无数值问题。

## 建议

1. 保留回采机制，使用按类型/等级成功率及固定条件通过率选模型，不追求平均
   等级恢复到 8 或 9。先验收最高墙、最高桥和最高坡，而不是直接继续长时间训练。
2. 做单因素对照：同样的 v4 回采课程、环境数、起始 stage2 权重及训练预算，
   对比单帧与六帧。现在的比较混合了历史、课程覆盖、环境数和 gap 判定变化，
   不足以给六帧结构定性。
3. 高墙验收固定 0.3/0.4/0.5/0.7 m/s，并关注 `base_contact`，避免较快指令
   下通过率掩盖慢速趴地。最高桥/坡增加随机条件复测，按评测结果选 checkpoint。
4. 若仍要求六帧保留旧能力，再考虑保持原策略输出的约束、逐步训练历史分支，
   或增加最高级复习占比；这些是下一轮候选方案，当前没有实现或验证。
5. 暂无依据统一增加抬腿奖励、放宽机身接触终止或修改求解器。动作与损失正常、
   奖励未改，而局部速度及历史敏感性已被实际测试观察到，应先处理这些明确缺口。

## 补充：比赛场地限高框架中段卡住

用户反馈六帧教师在 Robocon2027 框架中途卡住，旧教师没有这个现象。
已经在原生 CPU MuJoCo sim2sim 中复现。此前训练地形的名义条件 4/4
结果不能外推为比赛场地可靠通过，也没有覆盖手柄操作中的框内减速。

### 对比条件和结果

使用同一套 `XZ1IO`、PD 参数、`TeacherPolicy`、`TeacherHeightScan` 和
`HIMObservationBuilder`，策略无随机采样。原始场地文件保持不变。
正向从 `(-0.4,-2.02,0.30)`、yaw 0° 开始，反向从
`(2.4,-2.02,0.30)`、yaw 180° 开始。每条最多 25 s，不启用训练终止复位，
直接检查退出位置和实际碰撞接触。

| 操作 | 旧教师 | 六帧教师 |
| --- | --- | --- |
| 恒定 0.2 m/s，两个方向 | 两条均穿出 | 两条均卡在入口，25 s 未穿出 |
| 恒定 0.3/0.4/0.5/0.7 m/s，两个方向 | 八条均穿出 | 八条均穿出 |
| 0.4 m/s 进入，根位置到 x=0.85 后降到 0.2 m/s，正向 | 7.44 s 穿出 | 25 s 仍在 x=1.191，中段卡住 |
| 对称位置减到 0.2 m/s，反向 | 7.46 s 穿出 | 7.60 s 穿出 |
| 框内减到 0.1 m/s，两个方向 | 均穿出 | 均穿出，但中间及出口机身接触增多 |
| 框内停 1 s，再恢复 0.4 m/s，两个方向 | 均穿出 | 均穿出 |

“穿出”指根位置越过 x=1.95（正向）或 x=0.05（反向）且未倒地，
不代表全程所有足端都在框内、完全无擦碰或已完成竞赛有效性验收。
初版脚本的 `success` 还要求退出瞬间横向偏差小于 0.28 m；旧模型部分轨迹
因为侧偏而记为 false，即使已穿出且没有卡住。汇总 JSON 的
`crossed_exit` 与 `exit_lateral_check` 分开记录这两个判据。
以上每个条件均是单条确定性轨迹，不是统计意义上的通过率，不能据此认为
0.1 比 0.2 m/s 一定更好或断言某一速度的普遍成功率。

中段卡住时，碰撞记录为：

- 中间横梁 `limit_frame_beam_mid` 与 `base_link_primitive_1` 接触 725 个控制采样点；
- 出口横梁 `limit_frame_beam_y0` 与同一机身碰撞体接触 1014 个控制采样点；
- 最后 2 s 平均前进速度接近 0，指令仍为 0.2 m/s，机身根高度约 0.224 m。

接触采样为 50 Hz，表示多少个控制时刻检测到接触，不是连续接触时长，也不是
分离的碰撞次数。入口卡住的 0.2 m/s 案例则主要是前腿髋部、大腿持续顶住
入口横梁，不能把所有卡住都称为中间横梁碰撞。

在正常 0.4 m/s 正向轨迹，根位置 x≈1.0 的高度中位数旧模型约 0.190 m，
新模型约 0.209 m；框内减速后约为 0.196 m 与 0.219 m。新模型在这组
条件下低姿态保持的余量更小，实际接触支持这个判断。根高度并不等于机身顶面
净空，不能仅用上述数值推算是否一定会碰梁。

### 已确认的训练覆盖缺口

1. 几何不一致。`him_obstacles.py:175` 的训练框架只有前后两根横梁、
   两侧顶梁、四根立柱；`sim2sim/assets/Robocon2027.xml` 则另有
   x=1.0 的中间横梁及中间侧柱。最大难度的净空同为 0.29 m，结构却不同。
2. 速度不一致。保存的 `env.yaml` 为 `narrow_speed_range=(0.3,0.7)`。
   `XZ1CourseVelocityCommand` 对包括 low_frame 在内的课程地形覆盖普通
   `[-1,1]` 采样，使用前进速度和真值中心线纠偏，且关闭站立抽样。
   训练中没有专门覆盖框内降到 0.2/0.1 m/s 或停车再起步。
   这两轮都有该覆盖限制；旧模型能通过不代表它已被专门训练过这些操作。

### 消融结果与解释边界

以正向“0.4 进入、框内降到 0.2”这一已复现案例为基准：

| 六帧教师的诊断改动 | 结果 |
| --- | --- |
| 原始场地、正常六帧 | 25 s 卡住 |
| 临时关闭中间横梁的碰撞及高程可见性 | 8.16 s 穿出，出口机身接触 27 个采样点 |
| 同时关闭中间侧柱 | 8.16 s 穿出，与只移除横梁一致 |
| 原始场地，六帧全部替换为当前扫描 | 7.62 s 穿出，中间机身接触降为 3 个采样点 |

这是几何、速度与已学习的历史输入使用方式之间的交互问题的证据。
移除横梁同时改变了物理接触和感知输入，不能据此把效果全归因于其中一个；
重复当前帧改变了输入分布，也不等于重新训练单帧对照。
此外，恒定 0.2 m/s 的入口卡住在移除中间结构或重复当前帧后仍存在，
说明这些诊断改动都不是完整修复方案。没有证据将故障归结为历史顺序颠倒，
也没有证据证明六帧结构本身无法使用。

建议下一轮先使训练框架包含真实中间横梁，并补充限高框架的低速、框内减速、
停车恢复场景；保持同样几何、课程分布和预算做单帧/六帧对照。
先验证这些改动，再判断是否需要额外的净空/低姿态保持约束；不宜先统一
加大趴低奖励，以免损害平地、高墙及其他障碍的动作。
临时播放可用稳定 0.3–0.5 m/s 复核，但这不是训练修复或部署保障。

本次只增加诊断脚本、指标与报告，没有修改训练逻辑、奖励、模型或场地 XML。
