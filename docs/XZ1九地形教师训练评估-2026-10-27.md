# XZ1 九地形教师训练评估

分析对象：`Train/Nazarite/logs/rsl_rl/xz1_wmp_him_teacher/2026-10-27_14-05-54_stage2_nine_terrains/`。

结论：基础运动能力仍在，梅花桩、独木桥已表现出通过能力，但困难限高框架和 gap 尚未学会。课程存在跨类型沿用等级和连续成功／失败计数的实现问题，不能把平均等级接近 9 解释为九类地形全部掌握。建议先修课程，再处理这两类障碍，暂不把本轮作为九地形最终教师采集新一轮 WM／学生数据。

本次只做诊断、短时评测和结果归档，没有修改训练实现、奖励、地形或 checkpoint。

## 课程曲线的核心异常

以下为最后 100 次均值。成功列是训练内部的 EMA，不是独立评测成功率，也不是按全部回合直接计算的比例。

| 地形 | 成功 EMA | 平均等级（0–9） | 末段采样概率 |
| --- | ---: | ---: | ---: |
| 平地 | 77.76% | 8.78 | 7.55% |
| 高墙 | 95.56% | 8.74 | 4.72% |
| 窄楼梯 | 99.73% | 8.77 | 15.00% |
| 窄坡 | 91.63% | 8.76 | 10.00% |
| 梅花桩 | 65.20% | 8.74 | 14.34% |
| 独木桥 | 72.87% | 8.75 | 12.49% |
| 限高框架 | 0.219% | 8.78 | 19.99% |
| 轮胎阵列 | 88.03% | 8.79 | 5.92% |
| gap | 约 0 | 8.82 | 10.01% |

框架和 gap 约占 30% 的采样，却几乎不成功；它们仍处于高等级是课程状态串用造成的重要问题。平地本身不参与升降级，但也显示 8.78，进一步说明该等级描述的是被分配到该类型的环境当前等级，不是该类型独立掌握程度。

原因在 `Nazarite-src/nazarite/mdp/curriculums.py` 的 `terrain_levels_delta`：

1. 等级与连续成功／失败计数按环境维护。
2. 用当前地形结果更新等级后，每次 reset 又自适应重采样地形类型。
3. 类型改变时保留原等级；未发生升降级的连续计数也被保留。

使用同一函数和教师配置在内存构造状态，已复现：窄楼梯 level=8、此前连续成功 2 次，本次成功后升级，再分配到 gap，结果直接成为 gap level=9；此时 gap 历史回合数仍为 0。困难地形的失败计数还可能被下一次容易地形的成功打断，难以形成真正针对该类型的降级。

对照 WMP 原仓库 `legged_gym/envs/base/legged_robot.py`：地形类型在初始化分配，课程只改变行等级，没有每回合随机换类型后直接沿用等级的这一步。这是当前适配的课程状态管理问题，不能归因于参考仓库的原始做法。

最小、最接近参考的修复方向是固定类型，让各类型环境独立升降级；若保留自适应换类型，需要按类型分别保存等级和计数。仅在换类型时清空连续计数，仍不能修复等级串用。

## 实际通过情况

`model_1600.pt`：九类 × 难度 0/0.5/1 × 每组 4 回合，共 108 回合。速度 0.4m/s，seed=42，固定起点；关闭物理随机化、推扰、观测噪声和延迟。窄路线保留训练中的真值中心线命令纠偏，不能把路线保持全部归因于策略自身。

通过判定要求四脚越过障碍远端、机身额外前进 35cm、路线范围内、姿态稳定且至少两脚承重，保持 0.2s；真实失败优先于成功。

| 地形 | 低难度 | 中难度 | 高难度 |
| --- | ---: | ---: | ---: |
| 平地 | 4/4 | 4/4 | 4/4 |
| 高墙 | 4/4 | 4/4 | 4/4 |
| 窄楼梯 | 4/4 | 4/4 | 4/4 |
| 窄坡 | 4/4 | 4/4 | 4/4 |
| 梅花桩 | 4/4 | 4/4 | 4/4 |
| 独木桥 | 4/4 | 4/4 | 4/4 |
| 限高框架 | 4/4 | 4/4 | 0/4 |
| 轮胎阵列 | 4/4 | 4/4 | 4/4 |
| gap | 4/4 | 0/4 | 0/4 |

这些固定起点重复不是独立随机试验，也没有统计置信度保障。平地三种难度实际上是同样平地。新地形验收也不是完整比赛裁判：例如梅花桩允许一次单脚触地，未要求逐个桩体访问。

补充起点扰动：seed=43，最高难度，x±0.10m、y±0.05m、yaw±0.05rad，每类 8 回合。梅花桩 8/8，独木桥 8/8，轮胎 7/8。轮胎失败为 20s 超时、前进 2.25m；名义条件最高轮胎成功也需要约 16.8s，效率和稳健性仍需改善。本项同样没有开启物理随机化。

## 框架、gap 的失败轨迹

另外在单环境下分别复查旧教师 `model_999.pt` 和当前教师，在最高框架、中等 gap、最高 gap 各 1 回合，共 6 回合；记录机身、脚位置、受力和实际扫描值。

- 最高框架净空 0.29m：当前模型停在相对出生点 x≈0.769m，框架入口 x≈1.0m，20s 超时。机身中心已下降到约 0.262m，但没有成功穿过；末段 base 接触水平力约 31N。这是入口受阻，并非 reset 当下误触发或单纯“不肯降低姿态”。旧教师同条件同样超时。
- 中等 gap 宽约 0.19m、深约 0.255m：2.48s、机身前进约 0.720m 时，前脚下降至原地面下约 0.239m，并有明显承重接触，触发 `obstacle_ground_contact`。确实踩入沟内，不能通过放宽终止来当作通过。
- 最高 gap 宽 0.36m：停在 x≈0.618m，首沟入口 x≈0.8m，20s 超时。旧教师在该条件直接踩空失败；当前模型主要学到回避冒险，尚未学会跨越。

gap 的实际扫描中可见 0.255/0.36m 下陷，框架扫描也能命中顶部，未见“扫描全零、没有地形”问题。但教师使用 132 点自上向下高度扫描，只给命中表面高度，无法完整表达横梁下面的可通行净空；它不是深度相机。这种表征对限高框架有结构性局限，是否为主要失败原因还需净空观测消融或针对性训练验证，不能仅凭曲线断定。

现有 `pose` 在高墙和框架上已经关闭，不应再次把它当作未处理问题。固定步态、抬脚目标等是否妨碍深蹲尚未做因果消融，因此本轮不建议凭感觉整包放松姿态或统一提高抬腿奖励；gap 更需要合适的落脚跨度与落点，框架需要净空内的整机通过。

## 下一步建议

1. 优先修复课程类型、等级、连续计数的绑定，并验证“gap 连续失败会下降、楼梯成功不会给 gap 升级”。同时按类型和等级记录真实通过率及超时比例。
2. 给非有限恢复补充最小现场信息：类型、等级、根状态、关节状态、接触对。保留恢复机制，定位之后再改碰撞或求解参数。
3. 在修正课程后，从当前 checkpoint 权重热启动、重新建立低难度课程，分别复查框架净空 0.60→0.29m 与 gap 宽 0.02→0.36m；保留其他地形训练以防遗忘。恢复现有优化器／高等级状态并机械追加迭代，不是优先方案。
4. 如果低难度课程确实推进到瓶颈，再针对框架补充可解释的净空信息／验证下蹲约束，针对 gap 检查落脚规划与步态约束；逐项消融，避免同时替换奖励、传感器和课程。
5. 教师在目标九类和随机条件下验收后，再重新采集覆盖新障碍的深度序列、训练 WM 和蒸馏学生。旧 WM／学生的表现不能直接证明新增障碍已被覆盖。
