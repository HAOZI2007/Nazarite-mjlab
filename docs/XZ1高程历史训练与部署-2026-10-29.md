# XZ1 HIM＋高程输入训练

2026-10-30 更新：`Nazarite-WMP-HIM-Teacher-XZ1` 现在默认使用
**10 Hz 更新、单帧、不堆叠历史**的高程扫描，从基础 XZ1 HIM 权重热启动。
控制与 HIM 本体历史仍为 50 Hz，任务名称保留，
策略本身是 HIM＋高程编码器，不需要深度相机或 World Model。

## 独立配置入口

以下路径相对于 `Train/Nazarite/Nazarite-src/nazarite/config/train_config/XZ1_env_cfgs/`：

- `teacher_env_cfg.py`：教师自己的环境参数、九类地形及尺寸、传感器、观测、
  动作、速度采样、随机化、奖励、终止条件、课程、物理和 play 配置。
  顶部 `XZ1_TEACHER_*` 是常用参数；`XZ1_TEACHER_TERRAINS_CFG` 定义地形；
  `_build_xz1_teacher_env()` 定义各 manager。无需再修改 `him_env_cfg.py`。
- `teacher_rl_cfg.py`：`xz1_teacher_runner_cfg()` 显式定义 actor/critic 网络、
  HIM 估计器、PPO、rollout 步数、保存间隔和数值检查参数；
  `xz1_height_history_training_cfg()` 定义本训练入口的初始权重、迭代预算和实验名称。
  无需修改 `him_rl_cfg.py` 或共用的 `him_cfg.py` 默认参数。

`XZ1_TEACHER_SCAN_HISTORY_LENGTH=1` 和 `XZ1_TEACHER_SCAN_UPDATE_PERIOD=0.1`
在环境配置中集中定义，注册入口和 RL 配置均读取它们，避免环境和 actor 的
帧数、采样频率不匹配。采样周期须是控制周期 0.02 秒的正整数倍。
修改文件后重新启动训练生效。
若改变网络形状、高程网格或观测数值定义，还须同步权重加载及部署契约；这些变化
不能当作原 checkpoint 的普通 resume。

教师配置不再调用基础 HIM 的环境/训练配置工厂；奖励、地形生成和课程算法的
实现代码继续复用。配置拆分保持现有默认训练行为。

## 一行启动

在 `/home/haozi/桌面/Nazarite-mjlab/Train/Nazarite` 目录执行：

```bash
uv run --no-sync train Nazarite-WMP-HIM-Teacher-XZ1
```

默认配置：

- 当前文件配置为 600 个并行环境，100000 次 PPO 迭代，TensorBoard 日志。
- 从基础 HIM 模型（该训练目录最后一个 checkpoint）
  `logs/rsl_rl/xz1_him_complex/2026-10-25_22-04-31/model_31300.pt`
  加载 actor、critic 和 HIM 权重；重新开始优化器、迭代计数和地形课程。
- 单帧高程编码为 32 维；actor 主干输入为
  `47 当前本体观测＋3 估计速度＋16 HIM latent＋32 地形特征＝98` 维。
- 当前九类地形、奖励、终止条件和已修复的课程逻辑继续使用。
- 日志写入 `logs/rsl_rl/xz1_wmp_him_teacher/<时间>_height_single_10hz_from_him/`。

保留原 HIM 的 66 维 actor 输入权重，高程编码器新建，actor 新增的 32 维高程
特征对应权重初始化为零。初始动作与原 HIM 策略一致，再通过 PPO 学习使用高程；
没有加载旧地形教师的高程编码器，也没有从零学习基础行走。
默认 checkpoint 不存在时会明确报错，不会悄悄随机初始化。
每次重新执行上述指令都会从上述 HIM 权重开始一个新实验，并非自动续上最新实验。

继续一个已经训练过的 **单帧、10 Hz 教师模型**，例如再训练 1500 次迭代：

```bash
uv run --no-sync train Nazarite-WMP-HIM-Teacher-XZ1 --agent.resume True --agent.load-run '<单帧10Hz实验目录名>' --agent.load-checkpoint model_1000.pt --agent.max-iterations 1500
```

显式 `resume` 优先于默认热启动，恢复优化器和课程状态。原 HIM、旧 50 Hz
教师和三帧 10 Hz 教师都不能直接以新配置精确 resume；默认的一行指令
已替你完成从基础 HIM 到单帧高程教师的权重扩展热启动。

## 历史与导出接口

训练观测组 `teacher_scan` 为 `[环境数, 132]`，只有最新采样帧，没有历史维度。
132 点对应原有 12×11 扫描网格。共享 MLP 对每帧独立执行 `132→128→64→32`，
编码成 32 维送入 actor。

PPO rollout 保存最新原始扫描，每次更新使用当前编码器重新计算特征，保证编码器
梯度和新旧策略概率计算正确。没有把训练时已脱离梯度的 32 维缓存当作输入。
推理时编码器固定，也可以在部署端缓存编码后的特征。

控制仍为 50 Hz，高程输入每 5 个控制步采样一次，采样间隔 0.10 秒。
每次采样覆盖上一帧，不保留更早扫描。
采样间隔内保持最新原始高程输入（包括归一化所用机身高度），
不能用当前 base_z 重新处理旧扫描。
最新帧在控制时刻可能已有 0～0.08 秒采样龄期。
仿真底层射线及其他奖励/critic 传感器不统一降频，本次改变的是 teacher_scan
输入的采样；HIM 的六帧本体观测和 244 维 critic 维持原时序。
首次观测和单个环境 reset 后，立即采样该环境的新扫描，不沿用上一局输入。
新 checkpoint 记录帧数、顺序和采样间隔，加载时检查数值契约。

导出的 `policy.onnx` 输入为：

| 输入 | 形状 | 排列 |
| --- | --- | --- |
| `obs_history` | `[batch, 282]` | 6×47 本体观测，当前帧在前 |
| `teacher_scan` | `[batch, 132]` | 最新原始高程扫描 |

ONNX 内含 HIM、高程编码器和 actor。critic 继续使用原有 244 维训练观测，
不参与部署。原有视觉采集及学生流程的单帧配置保持兼容，测评器和教师 sim2sim
根据 checkpoint 自动选择帧数和采样周期；旧单帧/六帧 50 Hz 模型仍按原时序运行。
ONNX 是无状态网络，外部部署程序负责以 10 Hz 采样并在 50 Hz 控制期间保持最新扫描。

该路径不随本次训练输入改动自动切换；测试新模型时请显式传入新 checkpoint。

## 雷达部署约束

目前训练和 sim2sim 使用仿真真值扫描。实机需要把雷达高程图采样成同一网格：
x 为 -0.45～1.20 m、y 为 -0.75～0.75 m，间距 0.15 m，x 优先展开；
网格跟随机器人航向，输入为 `clip(base_z - 0.3 - terrain_z, -1, 1)`，缺测填 1。
高程图和机器人高度必须使用一致的坐标基准，并排除自身点云。

单帧输入要匹配训练的 10 Hz 时间语义，不应自行堆叠雷达历史帧。
雷达地图仍需时间同步、坐标统一；保持的是采样时的扫描，没有自动运动补偿
或重投影到当前机身坐标系。
雷达遮挡、缺测、噪声和限高框架的地图表达仍需实机前端验证。
单帧 10 Hz 输入不意味着已经解决 gap，也不等于雷达部署已经完成。
