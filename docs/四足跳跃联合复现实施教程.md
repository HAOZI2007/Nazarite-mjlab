# 四足跳跃联合复现实施教程

本文面向当前 `Nazarite-mjlab` 项目，目标是把下面两篇论文中的互补思想逐步复现出来：

1. **Curriculum-Based Reinforcement Learning for Quadrupedal Jumping: A Reference-free Design**：不依赖预先计算的关节轨迹，通过随机状态初始化、跳跃阶段奖励和自动课程学习训练跳跃。
2. **Integrating Trajectory Optimization and Reinforcement Learning for Quadrupedal Jumping with Terrain-Adaptive Landing**：用轨迹优化（Trajectory Optimization, TO）生成平地参考，再让 RL 学习跟踪；进入复杂地形落地阶段后，放宽关节参考跟踪，使腿能够主动适应落脚点。

本文不是把两篇论文简单相加，而是给出一个可以在本项目中逐步验证的联合方案：

```text
Stage A  无参考原地跳
   -> Stage B  目标条件平地跳
   -> Stage C  跳跃目标 Grid Adaptive
   -> Stage D  离线 TO 参考 + RL 跟踪
   -> Stage E  只在落地阶段放松关节参考
   -> Stage F  障碍物和崎岖地形课程
   -> Stage G  感知、在线落点规划和实机部署
```

重要说明：当前项目已经有成熟的 Go2 平地速度任务、Grid Adaptive 和 WTW，但**还没有一个已经接入训练入口的跳跃任务**。因此本文把代码分为两类：

- **第一阶段可直接实现**：`JumpCommand`、跳跃状态机、观测、无参考奖励、终止条件和 RSI。
- **后续扩展实现**：目标跳跃 Grid、地形障碍课程、CasADi/轨迹优化文件、TO 参考跟踪和落地 reward relaxation。

不要在现有 Trot WTW 任务中直接加入跳跃奖励。跳跃任务应该创建为独立任务，例如 `Nazarite-Jump-Flat-Go2`，这样不会破坏已经验证过的 `Nazarite-Velocity-Flat-Go2-WTW`。

## 1. 论文要解决的问题

### 1.1 为什么四足跳跃比普通速度跟踪难

普通速度任务可以在四脚接触地面时逐步修正误差。跳跃则包含明显的混合动力学阶段：

```text
支撑/蹲伏 -> 起跳 -> 腾空 -> 落地冲击 -> 恢复
```

每个阶段的控制目标不同：

| 阶段 | 主要目标 | 常见失败 |
| --- | --- | --- |
| 支撑/蹲伏 | 维持稳定、积累起跳动量 | 原地站立局部最优、不给起跳动作 |
| 起跳 | 四足协调施力、获得竖直速度 | 单腿先发力、机体前倾或侧翻 |
| 腾空 | 保持姿态、抬脚、准备落点 | 腿收拢不一致、落点偏差 |
| 落地 | 吸收冲击、四足重新接触 | 关节被参考轨迹锁死、弹飞或翻倒 |
| 恢复 | 快速重新获得稳定支撑 | 落地后继续振荡 |

如果只使用一个全程固定的 reward，通常会出现两种问题：

1. 姿态和能量正则过强，策略学会“站着不动”，因为这样最安全；
2. 参考关节轨迹过强，策略在平地有效，但复杂地形落地时没有自由度调整腿的位置。

### 1.2 第一篇论文的核心：让策略先看到跳跃状态

第一篇论文的关键不是一个神奇的奖励公式，而是训练分布设计：

- 先训练原地跳，再开放目标落点，再开放障碍物；
- 使用改进的 Randomized State Initialization（RSI），在 reset 时随机给机器人一定的高度和向上速度；
- 用 jump toggle 或目标条件告诉策略当前是否要跳；
- 奖励同时约束起跳、腾空、落地和低层正则项；
- 课程学习根据成功率自动扩大目标难度，失败时回退。

这样做的原因是：如果所有 episode 都从静止站立开始，而跳跃成功奖励只在很后面出现，策略几乎没有机会探索到有效的空中状态。

### 1.3 第二篇论文的核心：落地时不要死跟踪平地关节轨迹

第二篇论文先通过 TO 得到一条满足质心动力学、接触力、摩擦锥、关节运动学等约束的参考跳跃轨迹，再训练 RL 跟踪它。重点不在“永远精确跟踪”，而在于**按跳跃阶段改变 tracking 强度**：

- 起跳和腾空：严格跟踪 base/CoM 参考和关节参考，保证跳跃形状；
- 落地和恢复：继续跟踪 base 姿态，但显著放宽关节位置参考，让腿根据真实地形和冲击自行调整。

论文中将关节 tracking 的 Gaussian 核宽度从约 `sigma=0.2` 放宽到约 `sigma=2.0`，本质上是让“偏离平地参考”在落地时不再被过度惩罚。这个设计特别适合当前项目后续加入障碍物或高度不一致地面。

可以把论文中的 tracking 写成下面的抽象形式。`e_base` 是机体位置/姿态/速度误差，`e_joint` 是关节参考误差，`phase` 是当前跳跃阶段：

```text
R_track = exp(-||e_base||^2 / sigma_base^2)
        + exp(-||e_joint||^2 / sigma_joint(phase)^2)

sigma_joint(phase) = 0.2,  起跳/腾空
                    2.0,  落地/恢复
```

注意这不是简单把落地 reward 删除。落地时仍然需要 base 姿态、接触恢复、关节限位和冲击安全项；只放宽“腿必须和一条平地参考一模一样”这一条约束。

### 1.4 两篇论文的可复现要点

复现时应记录下面这些论文级别的设计，而不是只复制函数名称：

| 方面 | Reference-free 论文 | TO + RL 论文 |
| --- | --- | --- |
| 初始探索 | 改进 RSI，主动覆盖空中状态 | 由 TO 参考提供动作先验 |
| 目标 | 从原地跳到目标条件远跳、障碍跳 | 参考跳跃轨迹和地形自适应落地 |
| actor 输入 | 本体感知、目标命令、历史状态 | 本体感知、历史动作、参考状态、jump trigger |
| 训练信号 | 起跳、腾空、落点、对称、接触和正则 | base/joint reference tracking + 安全正则 |
| 落地处理 | 阶段奖励和接触约束 | 放宽落地阶段 joint tracking |
| 课程 | 自动扩展难度，保留旧难度样本 | 逐步增加障碍和地形扰动 |
| 参考轨迹 | 不需要 | 需要离线优化或预先生成 |

第一篇论文的可迁移思想是“课程和探索分布”，第二篇论文的可迁移思想是“参考不是硬约束”。当前项目要复现的正是这两个层次，而不是声称只增加一个 `jump_reference_reward` 就等于复现论文。

### 1.5 两篇论文如何联合

两篇论文的关系如下：

```text
第一篇：回答“怎样从零探索到跳跃，并逐步增加任务难度”
第二篇：回答“有了稳定跳跃形状后，怎样利用参考轨迹并适应非平地落地”
```

因此建议使用：

1. 用第一篇的 Stage I 训练出能跳的基础策略；
2. 用第一篇的目标命令和课程把原地跳扩展到远跳；
3. 用第二篇的 TO 为稳定跳跃提供参考轨迹；
4. 用第二篇的 phase-aware relaxation 处理复杂地形落地；
5. 用第一篇的地形/障碍课程和失败回退控制训练难度。

## 3. Stage A：无参考原地跳

这是最重要的第一步。不要一开始就加入障碍物、TO 轨迹和目标距离。先证明以下四个事实：

1. 机器人能从站立状态进入蹲伏和起跳；
2. 四条腿能够基本同步离地；
3. 能够落地并恢复站立；
4. 在 jump trigger 为 0 时能够稳定站立。

### 3.1 跳跃命令的数据结构

论文中的目标条件命令可以写为：

```text
g = [Delta p_des (3), Delta q_des (4), p_obs (3), dim_obs (3)]
```

再额外提供一个 `jump_trigger`。当前阶段只需要固定目标为零：

```text
target_landing = [0, 0, 0]
target_orientation = [1, 0, 0, 0]
obstacle_center = [0, 0, 0]
obstacle_size = [0, 0, 0]
jump_trigger = 0 或 1
```

这里的零障碍物并不代表永远不会加入障碍物，而是为了让 actor 的输入维度从第一天就和最终任务兼容。

### 3.2 `JumpCommandCfg` 和 `JumpCommand`

新建文件：

```text
Train/Nazarite/Nazarite-src/nazarite/mdp/jump.py
```

下面是一份连续的实现。它遵循当前项目的 `dataclass + CommandTerm` 风格。命令本身只负责“保存跳跃目标和 phase”，不直接修改机器人状态；奖励函数从这个 command term 读取状态。

```python
from __future__ import annotations

from dataclasses import dataclass
from enum import IntEnum

import torch
from torch import Tensor

from mjlab.envs.manager_based_rl_env import ManagerBasedRlEnv
from mjlab.managers.command_manager import CommandTerm, CommandTermCfg


class JumpPhase(IntEnum):
  """跳跃的离散阶段。数值会写入 phase_id，供 reward 读取。"""

  STAND = 0
  CROUCH = 1
  TAKEOFF = 2
  FLIGHT = 3
  LANDING = 4
  RECOVER = 5


JUMP_COMMAND_DIM = 14


@dataclass(kw_only=True)
class JumpCommandCfg(CommandTermCfg):
  """跳跃目标、触发方式和有限状态机参数。"""

  entity_name: str
  target_dx_range: tuple[float, float] = (0.0, 0.0)
  target_dy_range: tuple[float, float] = (0.0, 0.0)
  target_dz_range: tuple[float, float] = (0.0, 0.0)
  target_yaw_range: tuple[float, float] = (0.0, 0.0)
  obstacle_height_range: tuple[float, float] = (0.0, 0.0)
  obstacle_length_range: tuple[float, float] = (0.0, 0.0)
  jump_probability: float = 0.5
  stand_probability: float = 0.5

  # FSM 的阶段判断阈值。
  contact_force_threshold: float = 5.0
  takeoff_vertical_velocity: float = 0.4
  flight_height_margin: float = 0.04
  landing_vertical_velocity: float = -0.25
  recovery_height_tolerance: float = 0.05
  phase_timeout_s: float = 0.8
  max_jump_time_s: float = 3.0

  def build(self, env: ManagerBasedRlEnv) -> JumpCommand:
    return JumpCommand(self, env)

  def __post_init__(self) -> None:
    if self.jump_probability < 0.0 or self.stand_probability < 0.0:
      raise ValueError("jump_probability and stand_probability must be non-negative.")
    if self.jump_probability + self.stand_probability <= 0.0:
      raise ValueError("At least one of jump_probability/stand_probability is needed.")
    if self.contact_force_threshold <= 0.0:
      raise ValueError("contact_force_threshold must be positive.")
    if self.max_jump_time_s <= 0.0 or self.phase_timeout_s <= 0.0:
      raise ValueError("Jump time limits must be positive.")


class JumpCommand(CommandTerm):
  """生成目标跳跃命令，并维护每个并行环境的跳跃状态机。"""

  def __init__(self, cfg: JumpCommandCfg, env: ManagerBasedRlEnv) -> None:
    super().__init__(cfg, env)
    self._jump_cfg = cfg

    # [dx, dy, dz, qw, qx, qy, qz, obstacle_x, obstacle_y, obstacle_z,
    #  obstacle_length, obstacle_width, obstacle_height, jump_trigger]
    self._command = torch.zeros(
      self.num_envs, JUMP_COMMAND_DIM, device=self.device
    )
    self.phase_id = torch.full(
      (self.num_envs,), JumpPhase.STAND, dtype=torch.long, device=self.device
    )
    self.phase_time = torch.zeros(self.num_envs, device=self.device)
    self.jump_time = torch.zeros(self.num_envs, device=self.device)
    self.previous_contact = torch.zeros(
      self.num_envs, 4, dtype=torch.bool, device=self.device
    )
    self.target_reached = torch.zeros(
      self.num_envs, dtype=torch.bool, device=self.device
    )

    self.metrics["jump_phase"] = torch.zeros(self.num_envs, device=self.device)
    self.metrics["jump_trigger"] = torch.zeros(self.num_envs, device=self.device)
    self.metrics["jump_target_dx"] = torch.zeros(self.num_envs, device=self.device)

  @property
  def command(self) -> Tensor:
    """返回供 generated_commands 使用的 [N, 14] 命令。"""
    return self._command

  @property
  def trigger(self) -> Tensor:
    """返回 [N] 的 jump trigger，1 表示当前 segment 要求跳跃。"""
    return self._command[:, 13]

  def _sample_uniform(self, value_range: tuple[float, float], count: int) -> Tensor:
    return torch.empty(count, device=self.device).uniform_(*value_range)

  def _get_contact(self) -> Tensor:
    """读取 feet_ground_contact 的 found 字段，缺失时安全返回全 False。"""
    try:
      sensor = self._env.scene["feet_ground_contact"]
      found = sensor.data.found
      # 常见形状为 [N, 4, slots]；多个接触槽只要有一个成立即可。
      if found.ndim == 3:
        found = found.any(dim=-1)
      return found.to(dtype=torch.bool)
    except (AttributeError, KeyError, RuntimeError, ValueError):
      return torch.zeros(
        self.num_envs, 4, dtype=torch.bool, device=self.device
      )

  def _resample_command(self, env_ids: Tensor) -> None:
    count = len(env_ids)
    self._command[env_ids, 0] = self._sample_uniform(
      self._jump_cfg.target_dx_range, count
    )
    self._command[env_ids, 1] = self._sample_uniform(
      self._jump_cfg.target_dy_range, count
    )
    self._command[env_ids, 2] = self._sample_uniform(
      self._jump_cfg.target_dz_range, count
    )
    # 第一阶段只允许绕 z 轴改变目标姿态，四元数写成 yaw 的半角形式。
    yaw = self._sample_uniform(self._jump_cfg.target_yaw_range, count)
    self._command[env_ids, 3] = torch.cos(yaw * 0.5)
    self._command[env_ids, 4] = 0.0
    self._command[env_ids, 5] = 0.0
    self._command[env_ids, 6] = torch.sin(yaw * 0.5)
    self._command[env_ids, 7:13] = 0.0
    self._command[env_ids, 10] = self._sample_uniform(
      self._jump_cfg.obstacle_length_range, count
    )
    self._command[env_ids, 12] = self._sample_uniform(
      self._jump_cfg.obstacle_height_range, count
    )

    # 通过显式概率选择站立或跳跃。trigger 是策略输入，不是“自动命令”。
    total = self._jump_cfg.jump_probability + self._jump_cfg.stand_probability
    jump = torch.rand(count, device=self.device) < (
      self._jump_cfg.jump_probability / total
    )
    self._command[env_ids, 13] = jump.to(dtype=self._command.dtype)
    self.phase_id[env_ids[~jump]] = JumpPhase.STAND
    self.phase_id[env_ids[jump]] = JumpPhase.CROUCH
    self.phase_time[env_ids] = 0.0
    self.jump_time[env_ids] = 0.0
    self.target_reached[env_ids] = False
    self.previous_contact[env_ids] = self._get_contact()[env_ids]

  def _update_metrics(self) -> None:
    self.metrics["jump_phase"] = self.phase_id.float()
    self.metrics["jump_trigger"] = self._command[:, 13]
    self.metrics["jump_target_dx"] = self._command[:, 0]

  def _update_command(self, env_ids: Tensor | None) -> None:
    # 命令值只在 reset/resample 时更新；FSM 在 compute 中按仿真 dt 更新。
    del env_ids

  def _advance_phase(self, dt: Tensor) -> None:
    """根据接触、高度和速度更新状态机。"""
    robot = self._env.scene[self._jump_cfg.entity_name]
    root_pos = robot.data.root_link_pos_w
    root_vel = robot.data.root_link_lin_vel_w
    contact = self._get_contact()
    all_contact = contact.all(dim=1)
    any_contact = contact.any(dim=1)
    base_z = root_pos[:, 2]
    base_vz = root_vel[:, 2]
    nominal_z = self._env.scene.env_origins[:, 2] + 0.32
    above_nominal = base_z > nominal_z + self._jump_cfg.flight_height_margin

    # 保留旧状态，后面才能判断本步是否发生了阶段切换。
    old_phase = self.phase_id
    self.phase_time += dt
    self.jump_time += dt * (self._command[:, 13] > 0.5)
    phase = self.phase_id

    crouch_to_takeoff = (
      (phase == JumpPhase.CROUCH)
      & (base_vz > self._jump_cfg.takeoff_vertical_velocity)
    )
    takeoff_to_flight = (
      (phase == JumpPhase.TAKEOFF) & (above_nominal | (base_vz > 0.0))
    )
    flight_to_landing = (
      (phase == JumpPhase.FLIGHT)
      & any_contact
      & (base_vz < self._jump_cfg.landing_vertical_velocity)
    )
    landing_to_recover = (
      (phase == JumpPhase.LANDING)
      & all_contact
      & (torch.abs(base_vz) < 0.5)
      & (torch.abs(base_z - nominal_z) < self._jump_cfg.recovery_height_tolerance)
    )

    phase = torch.where(crouch_to_takeoff, JumpPhase.TAKEOFF, phase)
    phase = torch.where(takeoff_to_flight, JumpPhase.FLIGHT, phase)
    phase = torch.where(flight_to_landing, JumpPhase.LANDING, phase)
    phase = torch.where(landing_to_recover, JumpPhase.RECOVER, phase)

    # 阶段超时是安全兜底，不替代真正的物理判断。
    phase = torch.where(
      (self.phase_time > self._jump_cfg.phase_timeout_s)
      & (phase == JumpPhase.CROUCH),
      JumpPhase.STAND,
      phase,
    )
    phase = torch.where(
      (self.jump_time > self._jump_cfg.max_jump_time_s)
      & (self._command[:, 13] > 0.5),
      JumpPhase.RECOVER,
      phase,
    )
    self.phase_id = phase
    changed = phase != old_phase
    self.phase_time = torch.where(
      changed,
      torch.zeros_like(self.phase_time),
      self.phase_time,
    )
    self.previous_contact = contact

  def compute(self, dt: float | Tensor, env_ids: Tensor | None = None) -> None:
    super().compute(dt, env_ids)
    if env_ids is not None:
      return
    if isinstance(dt, Tensor):
      dt_batch = dt.to(device=self.device)
    else:
      dt_batch = torch.full((self.num_envs,), float(dt), device=self.device)
    self._advance_phase(dt_batch)


def jump_command(env: ManagerBasedRlEnv, command_name: str = "jump") -> Tensor:
  """把 JumpCommand 的完整向量暴露给 observation manager。"""
  command = env.command_manager.get_command(command_name)
  if command is None:
    return torch.zeros((env.num_envs, JUMP_COMMAND_DIM), device=env.device)
  return command


def jump_phase_one_hot(
  env: ManagerBasedRlEnv, command_name: str = "jump"
) -> Tensor:
  """返回 [N, 6] 的阶段 one-hot 观测。"""
  term = env.command_manager.get_term(command_name)
  if not isinstance(term, JumpCommand):
    return torch.zeros((env.num_envs, len(JumpPhase)), device=env.device)
  return torch.nn.functional.one_hot(
    term.phase_id, num_classes=len(JumpPhase)
  ).to(dtype=torch.float32)
```


### 3.3 推荐把 FSM 的自动推进改得更稳

初版可以用上面的接触和速度阈值，但真正训练时建议增加三个保护：

1. 接触必须连续维持若干仿真步，避免单个接触传感器噪声触发落地；
2. 进入 `FLIGHT` 必须满足“至少一帧所有脚离地”或 base 高度超过阈值，避免只因单脚离地被误判为跳跃；
3. 超时后要记录 `jump_phase_timeout`，方便在 TensorBoard 中区分“策略不会跳”和“阶段识别错误”。

不要把固定时间直接当作唯一 phase。固定时间可以作为 timeout 上限，但起跳和落地本质上由接触和速度决定。

## 4. 跳跃观测设计

### 4.1 actor 应该看到什么

第一篇论文的关键思想是让策略知道跳跃任务条件；第二篇论文还让策略看到参考状态。因此最终 actor 可以由下列部分组成：

```text
本体感知：
  base angular velocity
  projected gravity
  joint position relative to default
  joint velocity relative to default
  previous action

任务命令：
  target landing displacement
  target landing orientation
  obstacle center and dimensions
  jump trigger

阶段信息：
  jump phase one-hot 或 phase scalar

可选参考：
  q_ref
  base height/velocity reference
  reference phase
```

实机只有本体感知并不是问题：目标落点、jump trigger、参考相位是由上层规划器/遥控器给出的任务输入，不是外部视觉传感器；但障碍物中心和尺寸若来自视觉，就必须保证部署端也能提供同样语义的输入。否则训练时不能把视觉特权量放进 actor。

### 4.2 配置观测 term

新建跳跃任务配置时，可以在 `base_env_cfg.py` 的 WTW 观测写法基础上增加：

```python

  func=custom_jump.jump_command,
  params={"command_name": "jump"},
)
actor_terms["jump_phase"] = ObservationTermCfg(
  func=custom_jump.jump_phase_one_hot,
```

如果启用历史帧：

```python

  term.history_length = 10
for term in critic_terms.values():
  term.history_length = 3
```

训练前打印 observation manager 的维度，确认 actor 和 critic 维度与网络输入一致。特别检查：

- `jump_command` 是否为 14 维；
- `jump_phase` 是否为 6 维；
- actor 是否误把 obstacle 信息放进了实机不可提供的输入；
- history_length 是否把命令重复堆叠了 10 次；
- reset 后 phase 是否为合法 one-hot。

### 5.1 奖励分层

建议把跳跃 reward 拆成独立 `RewardTermCfg`，不要先写成一个不可观察的巨大组合项：

```text
任务层：
  jump_triggered
  takeoff_vertical_velocity
  target_landing_position
  target_landing_orientation

阶段层：
  stance/support contact
  swing foot clearance
  flight base height
  landing contact synchrony

稳定层：
  upright
  base angular velocity
  joint limits
  action rate
  torque/energy
```

这样做的好处是 TensorBoard 能回答“策略为什么失败”：是没有起跳、腾空高度不够、落点错，还是落地后恢复失败。

### 5.2 通用辅助函数

新建：

```text
Train/Nazarite/Nazarite-src/nazarite/mdp/jump_rewards.py
```

下面的函数使用当前项目的 `Entity` 数据字段和 `ContactSensor` 结构。足端顺序统一为 `[FL, FR, RL, RR]`。

```python
from __future__ import annotations

import torch
from torch import Tensor

from mjlab.entity import Entity
from mjlab.managers.scene_entity_config import SceneEntityCfg
from mjlab.sensor import ContactSensor
from nazarite.mdp.jump import JumpCommand, JumpPhase


def _jump_term(env, command_name: str) -> JumpCommand | None:
  term = env.command_manager.get_term(command_name)
  return term if isinstance(term, JumpCommand) else None


def _active_jump(term: JumpCommand) -> Tensor:
  return term.command[:, 13] > 0.5


def _contact(env, sensor_name: str, threshold: float = 5.0) -> Tensor:
  """返回 [N, 4] 的足端接触布尔值。"""
  try:
    sensor = env.scene[sensor_name]
    if not isinstance(sensor, ContactSensor):
      return torch.zeros(env.num_envs, 4, dtype=torch.bool, device=env.device)
    found = sensor.data.found
    if found.ndim == 3:
      found = found.any(dim=-1)
    if hasattr(sensor.data, "force"):
      force = sensor.data.force
      if force.ndim == 4:
        force = torch.linalg.vector_norm(force, dim=-1).amax(dim=-1)
      found = found & (force > threshold)
    return found.to(dtype=torch.bool)
  except (AttributeError, KeyError, RuntimeError, ValueError):
    return torch.zeros(env.num_envs, 4, dtype=torch.bool, device=env.device)


def jump_stance_contact_cost(
  env,
  sensor_name: str = "feet_ground_contact",
  command_name: str = "jump",
  force_threshold: float = 5.0,
) -> Tensor:
  """期望支撑相时惩罚足端没有接触。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  contact = _contact(env, sensor_name, force_threshold)
  active = _active_jump(term)
  expected_support = torch.isin(
    term.phase_id,
    torch.tensor(
      [JumpPhase.STAND, JumpPhase.CROUCH, JumpPhase.LANDING, JumpPhase.RECOVER],
      device=env.device,
    ),
  )
  missing = (~contact).float().mean(dim=1)
  return missing * active.float() * expected_support.float()


def jump_swing_clearance_reward(
  env,
  foot_height: Tensor,
  command_name: str = "jump",
  target_clearance: float = 0.08,
  std: float = 0.04,
) -> Tensor:
  """腾空阶段奖励足端达到净空高度。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  flight = (term.phase_id == JumpPhase.FLIGHT).float()
  height_error = torch.square(foot_height - target_clearance).mean(dim=1)
  return torch.exp(-height_error / max(std * std, 1.0e-6)) * flight


def jump_takeoff_reward(
  env,
  command_name: str = "jump",
  asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
  target_vertical_velocity: float = 1.0,
  std: float = 0.5,
) -> Tensor:
  """在起跳阶段奖励向上的 base 速度。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  robot: Entity = env.scene[asset_cfg.name]
  vz = robot.data.root_link_lin_vel_w[:, 2]
  phase_mask = (term.phase_id == JumpPhase.TAKEOFF).float()
  error = torch.square(vz - target_vertical_velocity)
  return torch.exp(-error / max(std * std, 1.0e-6)) * phase_mask


def jump_flight_height_reward(
  env,
  command_name: str = "jump",
  asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
  target_height: float = 0.48,
  std: float = 0.08,
) -> Tensor:
  """腾空阶段奖励机体达到目标高度。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  robot: Entity = env.scene[asset_cfg.name]
  base_z = robot.data.root_link_pos_w[:, 2]
  origin_z = env.scene.env_origins[:, 2]
  error = torch.square((base_z - origin_z) - target_height)
  flight = (term.phase_id == JumpPhase.FLIGHT).float()
  return torch.exp(-error / max(std * std, 1.0e-6)) * flight


def jump_landing_sync_cost(
  env,
  sensor_name: str = "feet_ground_contact",
  command_name: str = "jump",
  force_threshold: float = 5.0,
) -> Tensor:
  """落地阶段惩罚四脚接触不同步。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  contact = _contact(env, sensor_name, force_threshold).float()
  spread = contact.max(dim=1).values - contact.min(dim=1).values
  landing = torch.isin(
    term.phase_id,
    torch.tensor(
      [JumpPhase.LANDING, JumpPhase.RECOVER], device=env.device
    ),
  ).float()
  return spread * landing * _active_jump(term).float()


def jump_landing_target_cost(
  env,
  command_name: str = "jump",
  asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
) -> Tensor:
  """落地/恢复阶段惩罚 base 相对目标落点的平面误差。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  robot: Entity = env.scene[asset_cfg.name]
  current = robot.data.root_link_pos_w[:, :2]
  target = env.scene.env_origins[:, :2] + term.command[:, :2]
  error = torch.linalg.vector_norm(current - target, dim=1)
  landing = torch.isin(
    term.phase_id,
    torch.tensor(
      [JumpPhase.LANDING, JumpPhase.RECOVER], device=env.device
    ),
  ).float()
  return error * landing * _active_jump(term).float()
```

这些函数返回的是 cost 或 reward，最后通过配置中的 `weight` 决定正负。不要同时用“期望支撑未触地惩罚”和一个不读取 phase 的全局 `stance_contact` 去约束同一件事，否则会重新产生与 WTW 中类似的 reward 冲突。

## 6. 跳跃终止条件

### 6.1 必须终止的异常

跳跃任务至少要有：

```text
time_out
bad_orientation
base height too low
trunk/base illegal contact
episode jump timeout
```

大腿、髋部、小腿是否终止要谨慎。当前 WTW 经验已经说明：把小腿触地直接硬终止可能使 Pronking 根本学不出来，因为早期探索时策略需要机会从错误姿态恢复。第一阶段建议：

- 躯干触地：硬终止；
- 髋部触地：硬终止或较低力阈值终止；
- 小腿触地：先用 soft penalty；
- 足端接触：不是非法接触，不能误判为终止。

### 6.2 终止函数示例

新建 `jump_terminations.py`：

```python
from __future__ import annotations

import torch
from torch import Tensor

from mjlab.sensor import ContactSensor


def illegal_body_contact(
  env,
  sensor_name: str,
  force_threshold: float = 5.0,
) -> Tensor:
  """按接触传感器返回 [N] 的非法触地布尔值。"""
  try:
    sensor = env.scene[sensor_name]
    if not isinstance(sensor, ContactSensor):
      return torch.zeros(env.num_envs, dtype=torch.bool, device=env.device)
    force = sensor.data.force
    if force.ndim == 4:
      force = torch.linalg.vector_norm(force, dim=-1).amax(dim=-1)
    elif force.ndim == 3:
      force = torch.linalg.vector_norm(force, dim=-1)
    return force.amax(dim=-1) > force_threshold
  except (AttributeError, KeyError, RuntimeError, ValueError):
    return torch.zeros(env.num_envs, dtype=torch.bool, device=env.device)


def jump_time_limit(env, command_name: str = "jump") -> Tensor:
  """跳跃命令长时间没有进入恢复状态时终止。"""
  term = env.command_manager.get_term(command_name)
  if term is None or not hasattr(term, "jump_time"):
    return torch.zeros(env.num_envs, dtype=torch.bool, device=env.device)
  return (term.command[:, 13] > 0.5) & (term.jump_time > term._jump_cfg.max_jump_time_s)
```

## 7. 改进 RSI：让策略真正看到空中状态

### 7.1 RSI 的物理含义

reset 时不总是把机器人放在同一个站立状态，而是在安全范围内随机化：

```text
base z = nominal z + random height offset
base vertical velocity = random upward velocity
base angular velocity = small random value
joint pose = valid crouch/nominal pose + small noise
```

第一篇论文的思想是：当奖励稀疏时，直接从站立状态探索到有效跳跃很难；从部分起跳或腾空状态开始，可以让策略更快学会“如何完成空中和落地”。

### 7.2 为什么不能随便把高度和速度范围开大

如果 reset 出现穿地、关节极限、过大的下落速度，采样的不是有用的 RSI，而是大量不可恢复状态。建议分三阶段开放：

| 阶段 | 高度偏移 | 向上速度 | 目的 |
| --- | ---: | ---: | --- |
| A0 | `0.00-0.02 m` | `0.00-0.20 m/s` | 先验证实现 |
| A1 | `0.00-0.08 m` | `0.00-0.60 m/s` | 帮助起跳/腾空探索 |
| A2 | `-0.03-0.12 m` | `-0.20-0.80 m/s` | 覆盖落地恢复状态 |

### 7.3 RSI 事件函数

在 `jump.py` 或单独的 `jump_events.py` 中加入：

```python
import torch

from mjlab.entity import Entity
from mjlab.managers.scene_entity_config import SceneEntityCfg


def reset_jump_state(
  env,
  env_ids: torch.Tensor,
  asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
  height_offset_range: tuple[float, float] = (0.0, 0.02),
  upward_velocity_range: tuple[float, float] = (0.0, 0.2),
  angular_velocity_range: tuple[float, float] = (-0.1, 0.1),
) -> None:
  """在安全范围内随机初始化跳跃状态。"""
  robot: Entity = env.scene[asset_cfg.name]
  state = robot.data.default_root_state[env_ids].clone()
  origins = env.scene.env_origins[env_ids]

  state[:, :3] += origins
  state[:, 2] += torch.empty(
    len(env_ids), device=env.device
  ).uniform_(*height_offset_range)
  velocity = torch.zeros(len(env_ids), 6, device=env.device)
  velocity[:, 2] = torch.empty(
    len(env_ids), device=env.device
  ).uniform_(*upward_velocity_range)
  velocity[:, 3:6] = torch.empty(
    len(env_ids), 3, device=env.device
  ).uniform_(*angular_velocity_range)
  robot.write_root_link_pose_to_sim(state[:, :7], env_ids=env_ids)
  robot.write_root_link_velocity_to_sim(velocity, env_ids=env_ids)
```

当前 `Entity` 的 root state 布局是 `[position(3), quaternion(4), linear_velocity(3), angular_velocity(3)]`。代码使用项目已有的 `write_root_link_pose_to_sim()` 和 `write_root_link_velocity_to_sim()`，避免依赖一个在不同版本中可能不存在的 `write_root_state_to_sim()`。接入后先在 `num_envs=1` 下检查写回结果，再扩大并行环境。

事件配置示例：

```python

  mode="reset",
  params={
    "asset_cfg": SceneEntityCfg("robot"),

    "upward_velocity_range": (0.0, 0.20),
    "angular_velocity_range": (-0.10, 0.10),
  },
)
```

建议先只对部分 reset 环境启用 RSI，例如 25%，其余 75% 从正常站立开始。这样不会失去“从任务起点学会跳”的能力。

```python
    pattern=RingPatternCfg.single_ring(radius=0.03, num_samples=4),
  )
  terrain = ContactMatch(mode="body", pattern="terrain")
  hip = ContactSensorCfg(
    name="hip_ground_touch",
    primary=ContactMatch(mode="body", pattern=GO2_HIP_BODIES, entity="robot"),
    secondary=terrain,
    fields=("found", "force"),
    reduce="none",
    num_slots=1,
    history_length=4,
  )
  trunk = ContactSensorCfg(
    name="trunk_ground_touch",
    primary=ContactMatch(mode="body", pattern=(GO2_BASE_BODY,), entity="robot"),
    secondary=terrain,
    fields=("found", "force"),
    reduce="none",
    num_slots=1,
```

## 9. Stage B：目标条件平地远跳

当 Stage A 的成功率稳定后，才开放 `target_dx`。推荐顺序：

```text
0.00 m -> 0.10 m -> 0.20 m -> 0.35 m -> 0.50 m
```

不要一开始就让 `target_dx_range=(-1.0, 1.0)`，因为策略需要同时学习起跳高度、飞行时间、水平速度和落点控制。

### 9.1 目标落点误差

目标点应转换到环境局部平面坐标：

```python
target_xy = env.scene.env_origins[:, :2] + term.command[:, :2]
landing_error = torch.linalg.vector_norm(root_xy - target_xy, dim=1)
```

如果目标是相对于机器人当前朝向定义的，还要用当前 base yaw 将目标从 body frame 转到 world frame。不要把“目标在世界坐标”和“目标在机体坐标”混用，否则机器人转向时会出现系统性落点偏差。

### 9.2 Jump toggle 的训练分布

站立任务仍然需要采样，原因是最终部署时用户会切换“走”和“跳”。但比例要分阶段：

| 阶段 | standing | jumping |
| --- | ---: | ---: |
| A0 | 50% | 50% |
| A1 | 30% | 70% |
| B0 | 20% | 80% |
| 地形泛化 | 10-20% | 80-90% |

当 trigger 为 0 时，phase 不应继续产生跳跃状态；站立项应约束 base 速度、角速度和关节速度，避免策略在“不要跳”的命令下小幅晃动。

## 10. Stage C：把 Grid Adaptive 改成跳跃目标 Grid

当前 `GridAdaptiveVelocityCommand` 的 cell 是 `(x_velocity_index, yaw_velocity_index)`，并且激活 cell 采用均匀采样：

```text
P(cell) = 1 / N_active
```

跳跃任务不应该直接复用这个速度 Grid。跳跃课程的 cell 应代表“目标跳跃难度”，例如：

```text
cell = (target_distance_index, obstacle_height_index)
```

一个实用的 4 x 4 课程如下：

| distance | obstacle height |
| ---: | ---: |
| 0.00 m | 0.00 m |
| 0.15 m | 0.00 m |
| 0.30 m | 0.05 m |
| 0.50 m | 0.10 m |

### 10.1 为什么不直接修改 GridAdaptiveVelocityCommand

原有 command 内部有速度误差、yaw 误差和 WTW 接触质量门槛。如果把跳跃成功率硬塞进去，会产生三个问题：

1. velocity cell 和 jump target cell 的统计语义混在一起；
2. 一个 cell 既可能速度成功但跳跃失败，失败原因无法解释；
3. WTW 的 `grid_success` 不能再直接代表速度任务成功。

因此建议新增 `GridAdaptiveJumpCommand`，或把公共的“cell 统计/邻居扩展”抽成基类。

### 10.2 跳跃 Grid 的统计定义

每个跳跃 segment 结束时记录：

```text
success =
  jump trigger 已执行
  AND 至少发生起跳
  AND 进入落地/恢复
  AND landing_error < threshold
  AND 没有 trunk/hip illegal contact
```

不要只用 episode reward 判断成功。reward 可能被站立、姿态或能量项掩盖；课程需要一个可解释的物理事件判定。

### 10.3 修改现有 Grid 的最小办法

如果暂时不抽基类，可以复制 `commands.py` 中下列逻辑并改名：

```python
class GridAdaptiveJumpCommandCfg(CommandTermCfg):
  entity_name: str
  distance_bins: tuple[float, ...] = (0.0, 0.15, 0.30, 0.50)
  obstacle_height_bins: tuple[float, ...] = (0.0, 0.05, 0.10)
  min_cell_visits: int = 4096
  success_window_size: int = 4096
  success_rate_threshold: float = 0.8
  landing_error_threshold: float = 0.10
  max_new_cells_per_update: int = 1
```

具体的 `_sample_cells()`、ring buffer、`active_cells`、`cell_visits` 和邻居扩展可以逐行复用当前 `GridAdaptiveVelocityCommand`，但 `_settle_segments()` 的成功条件必须换成上面的跳跃事件判定。最终日志建议命名为：

```text
JumpGrid/success
JumpGrid/active_cells
JumpGrid/total_visits
JumpGrid/landing_error
JumpGrid/takeoff_rate
JumpGrid/recovery_rate
```

这和当前 WTW 中的 `grid_success`、`grid_active_cells`、`grid_total_visits` 分开，避免 TensorBoard 曲线含义混乱。

### 10.4 扩展和回退策略

推荐使用严格 frontier：

1. 初始只激活 `(0, 0)`，即原地无障碍跳；
2. 达到 `min_cell_visits` 且最近窗口成功率超过阈值，扩展一个相邻 cell；
3. 每次只扩展一个 cell，避免突然改变训练分布；
4. 新 cell 长时间失败时降低其难度或暂时冻结，不要反复激活/关闭造成振荡；
5. 保留 10-20% 已通过的旧 cell，防止灾难性遗忘。

这就是当前 WTW Grid 经验中“逐 cell 串行扩展”值得保留的部分，但跳跃课程的 cell 难度必须有明确物理含义。

## 11. Stage D：离线 TO 参考轨迹

### 11.1 TO 在做什么

第二篇论文的 TO 不是为了直接控制 Go2，而是先生成一个物理上合理的参考：

```text
输入：机器人质量、腿长、摩擦系数、目标距离、跳跃时间
变量：CoM/base 轨迹、接触力、关节角、落点
约束：动力学、运动学、摩擦锥、关节/力矩/接触约束
输出：可被 RL 读取的离散参考序列
```

第一阶段不需要立刻实现完整 CasADi 优化。可以先使用一条手工构造、经过仿真验证的参考，验证“参考读取和 phase-aware reward”是否正确；再替换成 CasADi 生成器。

### 11.2 建议的轨迹文件格式

每条轨迹保存为 `.npz`：

```text
t                 [T]
q_ref             [T, 12]
qdot_ref         [T, 12]
base_pos_ref     [T, 3]
base_quat_ref    [T, 4]
base_lin_vel_ref [T, 3]
base_ang_vel_ref [T, 3]
contact_ref      [T, 4]
phase_id         [T]
```

四元数统一使用项目当前约定的顺序；不要在生成器里用 `(x, y, z, w)`，在环境里却按 `(w, x, y, z)` 读取。

### 11.3 `jump_reference.py` 的完整读取和插值代码

新建：

```text
Train/Nazarite/Nazarite-src/nazarite/mdp/jump_reference.py
```

```python
from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path

import numpy as np
import torch
from torch import Tensor


@dataclass
class JumpReference:
  """单条跳跃参考轨迹，所有数组第一维都是时间。"""

  t: Tensor
  q_ref: Tensor
  qdot_ref: Tensor
  base_pos_ref: Tensor
  base_quat_ref: Tensor
  base_lin_vel_ref: Tensor
  base_ang_vel_ref: Tensor
  contact_ref: Tensor
  phase_id: Tensor

  @classmethod
  def load(cls, path: str | Path, device: torch.device) -> JumpReference:
    data = np.load(Path(path))
    required = (
      "t", "q_ref", "qdot_ref", "base_pos_ref", "base_quat_ref",
      "base_lin_vel_ref", "base_ang_vel_ref", "contact_ref", "phase_id",
    )
    missing = [name for name in required if name not in data]
    if missing:
      raise ValueError(f"Reference file misses fields: {missing}")
    values = {
      name: torch.as_tensor(data[name], dtype=torch.float32, device=device)
      for name in required
    }
    if values["q_ref"].ndim != 2 or values["q_ref"].shape[1] != 12:
      raise ValueError("q_ref must have shape [T, 12].")
    if values["contact_ref"].shape[1] != 4:
      raise ValueError("contact_ref must have shape [T, 4].")
    return cls(**values)

  def sample(self, time: Tensor) -> dict[str, Tensor]:
    """对一批时间点线性插值，超出范围时夹到首尾。"""
    time = time.clamp(self.t[0], self.t[-1])
    right = torch.searchsorted(self.t, time).clamp(1, len(self.t) - 1)
    left = right - 1
    denom = (self.t[right] - self.t[left]).clamp_min(1.0e-6)
    alpha = ((time - self.t[left]) / denom).unsqueeze(-1)

    def lerp(value: Tensor) -> Tensor:
      return value[left] + alpha * (value[right] - value[left])

    # 四元数不能直接无约束线性插值后使用；先线性插值再归一化是第一版
    # 足够稳定的实现，后续可替换为 SLERP。
    quat = torch.nn.functional.normalize(lerp(self.base_quat_ref), dim=-1)
    contact = (lerp(self.contact_ref) > 0.5).to(dtype=torch.float32)
    phase = self.phase_id[left]
    return {
      "q_ref": lerp(self.q_ref),
      "qdot_ref": lerp(self.qdot_ref),
      "base_pos_ref": lerp(self.base_pos_ref),
      "base_quat_ref": quat,
      "base_lin_vel_ref": lerp(self.base_lin_vel_ref),
      "base_ang_vel_ref": lerp(self.base_ang_vel_ref),
      "contact_ref": contact,
      "phase_id": phase,
    }
```

### 11.4 参考命令的生命周期

不要让每个 reward term 都自己从磁盘加载轨迹。正确关系是：

```text
JumpReferenceManager/CommandTerm
    -> 每步根据 jump_time 得到 q_ref/base_ref/contact_ref
        -> observation term 读取参考
        -> reward terms 读取同一份参考
```

可以先把 `JumpReference` 缓存在 `JumpCommand` 中，多个并行环境共享同一条参考；后续再按目标距离或障碍高度为不同 cell 选择不同轨迹。

## 12. TO reference reward 与落地放松

### 12.1 为什么要分别跟踪 base 和 joint

只跟踪关节角可能导致 base 姿态不正确；只跟踪 base 又可能让四条腿出现不一致。建议分开：

```text
base position/velocity/orientation tracking
joint position tracking
contact schedule tracking
```

每项独立记录，便于知道是“身体飞行轨迹错”还是“腿没有跟上”。

### 12.2 完整的 phase-aware tracking 代码

把下面函数放入 `jump_rewards.py`。它假设 `JumpCommand` 中额外挂载了 `reference_sample`，该字段由 `JumpReference.sample()` 每步更新。没有参考时返回 0，便于同一个 reward 文件服务 Stage A 和 Stage D。

```python
def _reference(term: JumpCommand, name: str, shape: tuple[int, ...], device) -> Tensor:
  value = getattr(term, "reference_sample", {}).get(name)
  if value is None:
    return torch.zeros(shape, device=device)
  return value


def jump_base_reference_reward(
  env,
  command_name: str = "jump",
  asset_cfg: SceneEntityCfg = SceneEntityCfg("robot"),
  std_position: float = 0.05,
  std_velocity: float = 0.30,
) -> Tensor:
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  robot: Entity = env.scene[asset_cfg.name]
  base_pos = robot.data.root_link_pos_w
  base_vel = robot.data.root_link_lin_vel_w
  pos_ref = _reference(term, "base_pos_ref", base_pos.shape, env.device)
  vel_ref = _reference(term, "base_lin_vel_ref", base_vel.shape, env.device)
  pos_error = torch.square(base_pos - pos_ref).mean(dim=1)
  vel_error = torch.square(base_vel - vel_ref).mean(dim=1)
  return torch.exp(-pos_error / max(std_position**2, 1.0e-6)) * torch.exp(
    -vel_error / max(std_velocity**2, 1.0e-6)
  )


def jump_joint_reference_cost(
  env,
  command_name: str = "jump",
  asset_cfg: SceneEntityCfg = SceneEntityCfg("robot", joint_names=(".*",)),
  takeoff_std: float = 0.2,
  landing_std: float = 2.0,
) -> Tensor:
  """起跳/腾空严格跟踪，落地/恢复放宽关节参考。"""
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  robot: Entity = env.scene[asset_cfg.name]
  current = robot.data.joint_pos[:, asset_cfg.joint_ids]
  reference = _reference(term, "q_ref", current.shape, env.device)
  error = torch.square(current - reference).mean(dim=1)
  landing = torch.isin(
    term.phase_id,
    torch.tensor([JumpPhase.LANDING, JumpPhase.RECOVER], device=env.device),
  )
  std = torch.where(
    landing,
    torch.full_like(error, landing_std),
    torch.full_like(error, takeoff_std),
  )
  # 返回 cost，配置时使用负 weight。
  return error / torch.square(std).clamp_min(1.0e-6)


def jump_reference_contact_cost(
  env,
  sensor_name: str = "feet_ground_contact",
  command_name: str = "jump",
) -> Tensor:
  term = _jump_term(env, command_name)
  if term is None:
    return torch.zeros(env.num_envs, device=env.device)
  actual = _contact(env, sensor_name).float()
  desired = _reference(term, "contact_ref", actual.shape, env.device)
  return torch.square(actual - desired).mean(dim=1)
```

这里的 `landing_std=2.0` 是“放宽误差核”的实现方式之一。它不是物理单位意义上的 2 米，而是 reward 归一化核宽度；实际项目中要根据关节角的量纲和 reward 数值重新标定。

### 12.3 在配置中实现论文式阶段权重

有两种做法：

1. 一个函数内部根据 phase 选择 `std`，如上面的 `jump_joint_reference_cost`；
2. 两个独立 reward term，各自只在对应 phase 生效。

当前项目倾向独立 term，因此建议：

```python
def _make_to_rewards() -> dict[str, RewardTermCfg]:
  return {
    "jump_base_reference": RewardTermCfg(
      func=jump_rewards.jump_base_reference_reward,
      weight=2.0,
      params={
        "command_name": "jump",
        "asset_cfg": SceneEntityCfg("robot"),
      },
    ),
    "jump_joint_reference": RewardTermCfg(
      func=jump_rewards.jump_joint_reference_cost,
      weight=-0.5,
      params={"command_name": "jump"},
    ),
  }
```

如果采用第二种“独立阶段项”，就把 `takeoff_std` 和 `landing_std` 分别写成两个函数，核心原则仍然是：落地时关节项弱，base 姿态和安全项不能完全关闭。

## 13. Stage F：地形和障碍物课程

### 13.1 平地训练和复杂地形的关系

两篇论文都不是简单地“直接把平地任务换成随机地形”。正确顺序是：

```text
平地稳定跳
 -> 低障碍、固定障碍位置
 -> 障碍高度逐步增加
 -> 障碍位置/宽度随机化
 -> 地面高度差和落脚面随机化
 -> 摩擦、质量、延迟等域随机化
```

第二篇论文尤其强调：参考轨迹可以来自平地，但 RL 在带障碍或地形扰动的环境中训练，通过落地阶段的放松使策略偏离平地关节参考。

### 13.2 接入当前 TerrainEntityCfg

当前平地任务使用：

```python
TerrainEntityCfg(terrain_type="plane")
```

后续地形任务改成 generator 时，结构应类似：

```python
cfg.scene.terrain = TerrainEntityCfg(
  terrain_type="generator",
  terrain_generator=_make_jump_terrain_generator(),
)
```

`_make_jump_terrain_generator()` 要做三件事：

1. 为每个 terrain level 定义障碍高度/间距；
2. 保证起跳区足够平整，避免策略还没起跳就踩到随机坑；
3. 为目标落地区保留一个可接受的支撑面，否则 reward 只会惩罚策略而没有成功可能。

不要一开始把所有地形类型等概率混合。应当把地形 level 作为课程变量，并保留一部分低难度旧样本防止遗忘。

### 13.3 地形课程成功条件

每个 level 记录：

```text
是否成功越过障碍
是否进入目标落地窗口
落地后是否恢复
最大碰撞力
落地姿态误差
```

成功率只在 episode 或 jump segment 结束时结算，不能每个仿真 step 直接累加，否则一个长时间 episode 会被重复计数。

## 14. 域随机化的分阶段设计

域随机化不是越早越强越好。推荐如下：

| 阶段 | 随机化 |
| --- | --- |
| Stage A 调试 | 关闭推力、固定摩擦、固定质量；只保留极小 encoder noise |
| Stage A 收敛 | 摩擦、质量、COM 小范围 |
| Stage B 远跳 | 摩擦、payload、关节偏置、PD gain 小范围 |
| Stage D TO tracking | 参考轨迹固定，随机化摩擦/延迟/电机强度 |
| Stage F 地形 | 地形、摩擦、恢复系数、延迟、COM 全部逐渐开放 |

实机部署要求 actor 观测和训练一致，但 critic 可以使用训练期间的特权信息。不要把真实部署拿不到的“真实接触力、障碍物真值、未来地形”直接加入 actor。

当前 WTW 任务在 play 中保留随机推力用于抗扰测试，但训练阶段通常关闭推力帮助策略先学会指定步态。跳跃任务也建议：先关推力学会跳，再单独开启推力做鲁棒性微调，而不是从第一步就把跳跃和大推力同时交给策略。

## 15. actor/critic 和实机部署边界

推荐配置：

```text
actor：本体角速度、重力投影、关节位置/速度、历史动作、jump command、phase
critic：actor 观测 + 真实 base 状态、接触真值、参考误差、地形特权信息
```

部署时只导出 actor。下面这些内容可以只给 critic：

- 仿真真实接触力；
- 真实 base 世界坐标；
- 目标地形的精确高度场；
- TO 参考与真实状态的内部误差；
- 训练中才存在的随机化参数。

但 jump trigger、目标落点和参考相位若被 actor 使用，部署端必须由遥控器或上层规划器提供。若部署端没有障碍物感知，就先训练不使用 obstacle center/size 的版本，不要训练时偷偷依赖它们。

## 16. play 网页控件建议

当前 WTW 已有网页行为参数控制器，`WTWBehaviorCommand.create_gui()` 会暴露 frequency、body height offset、pitch、stance width 和 swing height。跳跃任务可以采用同样的模式，增加：

```text
Enable jump override
Jump trigger
Target dx
Target dy
Target yaw
Obstacle height
Reset jump phase
```

控件回调不要直接从浏览器线程写仿真张量。正确模式是：

```text
GUI 回调只更新 slider 状态
仿真 compute() 每步读取 slider
compute() 在仿真线程统一写 command
```

这个原则与当前 WTW GUI 的实现一致，可以避免并发写入导致的偶发崩溃和一帧内命令不一致。

## 18. 分阶段验收标准

每一步通过后再进入下一步：

### Stage A0：代码和物理检查

- `num_envs=1` 可以 reset；
- 命令维度正确；
- phase_id 不越界；
- feet sensor 形状为 `[N, 4]`；
- 无 NaN/Inf；
- 所有终止条件能在 play 中被触发。

### Stage A1：无参考原地跳

- trigger=0 时稳定站立；
- trigger=1 时大多数 episode 能离地；
- 四脚离地/落地不同步程度下降；
- 躯干和髋部触地率下降；
- recovery rate 不为零。

### Stage B：目标平地远跳

- `target_dx=0.10 m` 成功率稳定后再增加距离；
- 落点误差随课程难度单调增加但不突然发散；
- 旧的短距离 cell 成功率没有明显遗忘。

### Stage D：TO tracking

- 平地参考下起跳/腾空动作不比无参考策略差；
- reference joint error 在起跳和飞行阶段较低；
- landing joint error 可以变大，但 base 姿态和恢复率不下降；
- 放宽 landing std 后复杂地形成功率提升。

### Stage F：障碍和地形

- 每次只增加一个难度方向；
- 低难度旧样本保留；
- 障碍高度增加时成功率下降可解释，而不是所有 cell 同时崩溃；
- play 能单独固定障碍和落点复现失败案例。

## 19. 常见错误和排查顺序

### 19.1 一给 jump trigger 就直接倒

依次检查：

1. reset pose 是否已经接近蹲伏极限；
2. `jump_takeoff` 是否真的只在 TAKEOFF 生效；
3. `jump_stance_contact` 是否把起跳早期的短暂离地误判成错误；
4. trunk/hip force threshold 是否过低；
5. action scale、PD gain 和仿真 timestep 是否与 Go2 baseline 一致。

### 19.2 四脚不同步

先看实际 contact 曲线，再看 reward：

```text
FL FR RL RR contact
```

如果传感器顺序错了，任何同步奖励都会把策略往错误方向推。当前项目统一约定 `[FL, FR, RL, RR]`，新增传感器和 reward 必须保持这个顺序。

### 19.3 训练成 Trot 而不是 Pronking

检查是否残留：

- 不读取 phase 的 air-time 奖励；
- 全局 stance contact 奖励；
- 过强 default pose；
- 过强速度/动作速率正则；
- reset phase 与初始站姿不一致；
- 训练推力太强。

Pronking 需要组接触约束，而不是只约束每条腿各自“偶尔摆动”。

### 19.4 TO 轨迹看起来正确，但 RL 不跟

检查：

1. 四元数顺序；
2. world/body frame 转换；
3. 轨迹时间单位是秒还是归一化 phase；
4. `q_ref` 的关节顺序是否和 Go2 action 顺序一致；
5. reference 是每个环境都能拿到，还是只有 CPU 上的一份 numpy；
6. landing relaxation 是否错误地从起跳阶段就启用。

### 19.5 高度一直上漂

不要只增大高度奖励。先确认：

- body height 是绝对目标还是相对 offset；
- base 高度测量是 world z 还是相对 terrain 高度；
- 起跳阶段是否仍然被高度目标压制；
- 速度跟踪是否通过前倾/抬高机体获得额外收益；
- TO base reference 是否和环境 origin 对齐。

当前 WTW 已经使用“`base_height_target + body_height_offset`”的语义；跳跃任务应明确区分 `nominal_height`、`takeoff_height` 和 `landing_height`，不要复用一个全程固定高度目标。

## 20. 推荐实际实施顺序和命令

### 第一步：先只写代码，不加复杂课程

完成：

```text
mdp/jump.py
mdp/jump_rewards.py
mdp/jump_terminations.py
go2_jump_env_cfgs.py
任务注册
```

然后用单环境检查：

```bash
cd /home/haozi/桌面/Nazarite-mjlab/Train/Nazarite
uv run play Nazarite-Jump-Flat-Go2
```

### 第二步：训练 Stage A0

配置：

```text
target_dx = 0
obstacle = 0
RSI 关闭或极小
推力关闭
固定摩擦
只训练 jump trigger + stand
```

### 第三步：增加 RSI 和原地跳比例

先只增加向上速度，再增加高度范围；如果 takeoff rate 上升但 recovery rate 下降，说明探索到了空中但没有学会落地，不要继续扩大目标距离。

### 第四步：开放目标距离和 Jump Grid

一次只开一个相邻 cell，使用 `min_cell_visits + success_window_size` 控制扩展，不要和当前速度 Grid 共用统计量。

### 第五步：加入手工参考，验证 TO tracking 接口

手工参考跑通后，再写 CasADi 轨迹优化器。这样可以把“TO 求解失败”和“RL 参考读取失败”分开。

### 第六步：启用 landing relaxation

先在平地确认起跳质量不下降，再在低障碍地形验证落地成功率是否提高。若放宽后策略只会乱踢腿，说明 base/reference/contact 的约束不够，而不是应该重新把 joint std 调回极小。

### 第七步：地形和实机准备

逐步加入障碍、摩擦、延迟、关节偏置和推力；最后用与 actor 完全一致的本体感知输入导出部署模型。

## 21. 当前项目中哪些代码可以直接复用，哪些不能直接复用

| 组件 | 是否直接复用 | 说明 |
| --- | --- | --- |
| Go2 robot config | 可以 | 复用 `get_go2_cfg()` 和 action scale |
| ContactSensor 配置 | 基本可以 | 复用足端、髋、躯干传感器，但核对顺序和 force shape |
| `GridAdaptiveVelocityCommand` | 不直接复用 | 统计目标是速度，不是跳跃成功 |
| WTW behavior/phase | 不直接复用 | WTW phase 是周期步态，跳跃 phase 是有限状态机 |
| 通用 upright/limit/action-rate reward | 可以 | 重新标定权重 |
| air-time/全局 stance contact | 不建议直接复用 | 很容易和 jump phase 或组同步目标冲突 |
| 当前 plane terrain | Stage A/B 可复用 | 先用平地验证跳跃 |
| 当前 WTW GUI 模式 | 可以参考 | 跳跃控件要写入 JumpCommand |
| 当前 play 随机推力 | 后期再用 | 初期先关闭，后续作为鲁棒性测试 |

## 22. 最终建议

当前项目最稳妥的联合复现路线是：

1. 保留现有 WTW 任务作为独立的速度/步态基线；
2. 新建 `Nazarite-Jump-Flat-Go2`，不要把 jump reward 混进 WTW；
3. 先实现第一篇论文的无参考原地跳和 RSI；
4. 用明确的 `STAND -> CROUCH -> TAKEOFF -> FLIGHT -> LANDING -> RECOVER` 状态机记录跳跃过程；
5. 再把目标落点扩展成独立的 Jump Grid；
6. 用手工参考验证第二篇论文的 tracking 接口，再接入 CasADi TO；
7. 起跳/腾空阶段严格跟踪，落地阶段提高关节 tracking 的 `std`，保留 base 姿态、安全和接触恢复约束；
8. 最后才加入障碍物、崎岖地形和更强域随机化。

一句话概括：**第一篇负责把“跳跃能力和课程”训练出来，第二篇负责把“参考轨迹和复杂地形落地适应”接上去。** 当前 Nazarite-mjlab 的 WTW/Grid 经验可以复用工程结构和课程统计方式，但不能把周期步态的 phase、速度 cell 和跳跃 FSM 混成一个命令或一个成功率。
