## WM 序列覆盖

| 窗口长度 | 训练可用窗口 | 验证可用窗口 | 训练可用 Episode | 验证可用 Episode |
| ---: | ---: | ---: | ---: | ---: |
| 32 帧 | 99,668 | 52,781 | 2,571/2,592 | 1,276/1,296 |
| 64 帧 | 30,963 | 17,628 | 1,492/2,592 | 783/1,296 |

32 帧下，九类地形的所有等级在训练集与验证集中都有有效序列。
64 帧会丢弃大量短 episode，特别是限高框架、高墙和梅花桩；
而且当前采样器按所有合法窗口随机抽样，较长 episode 会贡献更多训练样本。
因此首轮采用 32 帧：既利用已完成的真实序列，也避免跨 episode 拼帧或填充终止状态。
32 帧表示 3.2 秒时序上下文，不改变 10 Hz 相机、五步动作标签或参考网络结构。

## 下一步：WM 预训练

`cd /home/haozi/桌面/Nazarite-mjlab/Train/Nazarite` 后执行：

```bash
uv run --no-sync python -m nazarite.scripts.pretrain_xz1_wmp \
  --dataset logs/wmp_data/xz1_teacher_stage4_nine_v2 \
  --output logs/wmp_pretrain/xz1_wm_stage4_nine_v1 \
  --updates 1000 \
  --batch-size 4 \
  --batch-length 32 \
  --eval-interval 100 \
  --validation-batches 16 \
  --seed 42 \
  --device cuda:0
```

这是一轮**新模型**的 1000 次起步预训练；不要传 `--resume`。
输出目录必须不存在。模型仍使用参考仓库 Dreamer WMP 实现与已有默认网络尺寸。
训练完成后保留 `wm_1000.pt`、`metrics.json` 和 manifest SHA256，再评估 held-out
验证种子的未来深度预测、各地形 loss 和特征是否塌缩，再决定是否续训到更高步数。

有余力时再对比 64 帧窗口；需要使用另一个全新输出目录和同一数据，从头训练，
不能把不同窗口设置续进同一 checkpoint。若训练中断，输出目录会保留为部分运行，
不要覆盖；检查最后一个完整 checkpoint 后，用新的输出目录从该 checkpoint 续训。

完成 WM 后，视觉蒸馏必须引用同一 stage4 教师 checkpoint 和这个新 WM checkpoint；
学生代码会根据教师 SHA256 与 WM 数据 manifest 做来源校验。
