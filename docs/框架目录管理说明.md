# 框架清理与目录管理

2026-10-31：移除 DELTA 与 SMP 专用实现，保留其他 XZ1/Go2 任务。

## 清理范围

删除 DELTA 编码器、残差/Direct/attention 模型、专用地形和观测、环境与
RL 配置、sim2sim 部署模式及专用测试；删除 SMP prior、guidance、参考教师、
任务配置和 `smp-pretrain` 项目入口。同步移除 mjlab 中 DELTA 专用模型参数、
play 消融和 viewer 面板。

共享地形、相机、训练和 viewer 基础设施继续保留。`terrain_levels_delta`
虽然带历史名称，实际由 XZ1/Go2 HIM 使用，因此保留其行为及 `_delta_*`
续训状态字段。这不是残留的 DELTA 任务。旧设计说明归档到
`docs/archive/delta/` 和 `docs/archive/smp/`，其中命令不适用于当前版本。
历史数据、权重和训练日志属于本地实验资产，不随源码清理删除。

## 兼容规则

旧 `sim2sim.main`、`sim2sim.xz1_him`、`sim2sim.xz1_teacher`、
`sim2sim.xz1_wmp` 和旧 `nazarite.scripts.*` 命令继续转发到新入口。
旧 `XZ1_env_cfgs`、`env_cfgs`、平铺 MDP/runner 路径中剩下的文件仅负责兼容
导入，不再存放任务实现。它们让已有脚本、配置中的类路径和 checkpoint 引用
继续工作。新增代码必须引用上述分类目录，不在旧位置新增实现。

任务 ID、机器人参数、观测/动作契约、奖励、地形课程和默认模型路径保持不变。
新增机器人在 `tasks/` 和训练配置中建立独立目录；跨机器人复用的功能放入
`shared/`；算法模块按 HIM/WTW/WMP/FR-Net 分类，避免将任务代码重新平铺。

## 验证方法

先保存 12 个保留任务的训练/播放/runner 配置快照，再删除专用实现。
删除后只有未使用的 DELTA 模型配置字段消失，其余配置相同；目录迁移后
配置快照完全相同。清理前后同一组 210 项测试全部通过，迁移后扩大回归至
316 项测试通过，覆盖 GPU 步进、PPO、教师续训/导出、WMP 和 CPU sim2sim。
最终检查结果见 [清理验证记录](框架清理验证记录.md)。
